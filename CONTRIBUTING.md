# Contributions

Use “Suggest a source” for additions and “Correct a record” for errors. A primary publication or official documentation link and a short relevance explanation are sufficient. Optional relationship disclosures help readers assess context. You do not need to write an editorial profile.

Maintainers check scope, duplicates and metadata before inclusion. A submission remains an open issue until accepted or closed with a reason. Use labels `submission`, `correction`, `needs-verification`, `accepted`, and `out-of-scope` to track decisions. Link the resolving commit or pull request when closing a submission.

For pull requests, edit data/records.json and run npm test. Preserve stable IDs. Record preprint and published-version links in aliases after confirming identity. Do not merge different papers about the same system. Preserve provenance and corrections in Git history.

Source type, relevance, and review depth are distinct fields. Imported records use “Metadata pending verification” and a null verifiedDate. “Publication record checked” means checking the primary record and abstract, not the full paper. “Documentation checked” describes official product documentation. “Full paper reviewed” requires a linked review note. Implementation inspection and independent reproduction require separate evidence reports; never infer them from a paper review. Advance review dates only after actually checking the source.

Unresolved primary links remain visible in the verification queue. Do not invent metadata, citations, results or review work. Preserve exact publication titles when verified. Store original summaries rather than copied abstracts. Quantitative claims need experimental context. Author-submitted work follows the same criteria as other submissions.

New entries need not have profiles. Profiles additionally require name, summary, interface, caveat, tags and evidence. Existing research and industry presentation fields are retained for website compatibility. Additional provenance fields may document the import or correction.

Contributions of original editorial content are offered under the reuse terms in README.md; utility code is MIT licensed. Contributors must have the right to submit their material.
